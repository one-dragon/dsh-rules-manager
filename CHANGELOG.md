# Changelog

All notable changes to this project are documented here.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **Seven more rule conventions, and three new source shapes.** Trae CN, Qoder CN, Lingma, JetBrains AI Assistant, Antigravity, Kiro and Augment Code join the table (22 conventions in all), each with the official page it was verified against. Three shapes the table could not express are now modelled: **a second directory per tier** (Cline's `.clinerules` *and* `.cline/rules`, `~/.cline/rules` *and* `~/Cline/Rules`; Junie's legacy `.junie/guidelines`), **a declared single file per tier** (Copilot's `copilot-instructions.md`, Devin's and Windsurf's`global_rules.md`, Roo Code's `.roorules`, Augment's `user-guidelines.md` and `.augment-guidelines`), and **environment-resolved directories** (`CLINE_DIR`, `COPILOT_HOME`, `KIRO_HOME` beside the existing `DSH_AGENTS_HOME`). A file root is read whole and derives always-on, because the table naming the file *is* the declaration. Cursor's extension list was narrowed to `.mdc` — its rules system ignores a plain `.md` — and the classify gate learned Kiro's `inclusion` field and Augment's `type: always_apply | agent_requested` values. Verified against upstream in a separate pass: Cline's OneDrive path, Augment's `type` table and "user rules are always treated as always_apply", Kiro's inclusion modes and `KIRO_HOME`, Antigravity's required-frontmatter global rules, Copilot CLI's two user-level locations, Roo's file fallback and fixed global location. Two claims were dropped after that pass: Kiro's `fileMatch` was **not** documented as a rename of `auto`, and Windsurf's user-level `global_rules.md` path survives only on the localized official pages (the English page now redirects to Devin's documentation).
- **`AGENTS.md` / `CLAUDE.md` / `GEMINI.md` are explicitly out of scope.** Several of the sources above document such a file next to their rules directory (Junie's `.junie/AGENTS.md`, Devin's `~/.config/devin/AGENTS.md`, Antigravity's four always-on files, Kiro's note that `AGENTS.md` ignores `inclusion` modes), and Codex, Gemini CLI and OpenCode use that family *instead of* a rules directory. None of them is declared here: DSH ships `@deepseek-ai/dsh-agent-instructions`, which loads that chain by directory level, so scanning it again would put the same text in the prompt twice. The source table declares only each tool's rules tier, and two delivery checks now fail the build if a tier ever names one of those files.
- **Eleven more rule conventions.** Trae, Qoder, Cline, Roo Code, Devin / Windsurf, legacy Windsurf, GitHub Copilot, Junie, Amazon Q, Tabnine and Continue are scanned read-only alongside the original four. Each entry carries the official documentation URL it was verified against, and a source whose user tier is not documented upstream leaves `userPath` unset instead of scanning a guessed path. GitHub Copilot is restricted to `*.instructions.md` through a new suffix filter; Roo Code also accepts `.txt`. WorkBuddy needs no entry of its own: its IDE rules are the CodeBuddy convention.
- **One answer per convention for a file with no frontmatter.** `frontmatterOptional` was a single boolean, so every convention that set it got the same answer: always-on. Upstream does not agree. CodeBuddy documents an always-applied rule whose frontmatter holds nothing but a comment; Cursor reaches a file with none of `alwaysApply`, `description` and `globs` only through `@`-mention; Antigravity requires `trigger` outright. The field is now `emptyRuleType: always | manual | none`, and all 22 sources declare their own answer — 18 always, GitHub Copilot manual (a `.instructions.md` is scoped by `applyTo`), and Cursor / `.agents` / Antigravity's global tier none. Four parsing fixes ride along: a rule that declares only `paths` or `globs` derives to requested instead of manual (Claude Code, Continue, Cursor); `trigger: agent` is recognised, as Devin and the legacy Windsurf CLI document it; a `---` fence with nothing between the markers is a valid fence rather than a missing one; and Copilot's `applyTo` plus Continue's `name` are read, so a file carrying only those is no longer discarded. New diagnostic `list.empty` names a list field that was read as zero entries, which is how Cline's `paths: []` ("the rule never activates") reads on screen.
- **Twenty-two official brand marks in the panel.** The source chip renders the vendor's own SVG for CodeBuddy and its intranet variant, Cursor, Claude Code, Trae, Trae CN, Qoder, Qoder CN, Cline, Roo Code, Windsurf, GitHub Copilot, Junie, Amazon Q, Tabnine, Continue, Lingma, JetBrains AI Assistant, Antigravity, Kiro, Augment Code and Devin — vendored into `src/client/brand-icons.ts`, because a vendor URL rotates with the build while committed bytes do not. A mark is taken from the vendor's own site or repository and the entry records the URL, the HTTP status, what was stripped and what was renamed; a convention that publishes nothing usable keeps the two-letter chip instead of an invented glyph. One does: `.agents` is a shared directory rather than a vendor. Trae CN shares the TRAE glyph because it is the same mark on both sites. Qoder CN and Devin were added later: qoder.cn serves a byte-identical copy of the Qoder mark, and Devin's favicon is the only vector asset the site has, fetched once the TLS handshake stopped failing.
- **Clickable diagnostics.** The diagnostics number in the stat bar is now a button that filters the list down to the rules carrying diagnostics, and each rule's diagnostics expand into code plus detail instead of living in a `title` tooltip.
- **Workspace switcher.** When the host knows more than one DSH workspace, the panel offers them in a dropdown and every read and write carries `?workspace=<path>`, so switching workspaces no longer snaps back on the next toggle.
- **File-scoped rules attach themselves once the session touches a matching file.** `paths` / `globs` were parsed and carried on every rule from the first release, but nothing ever matched them: a rule scoped to `src/**/*.ts` stayed an index line no matter what the session opened. Attachment is now observed from the tool pipeline itself — a `tools/result` listener reads the frozen outcome of every `read`, `write`, `edit`, `read_image`, `str_replace_editor` and `apply_patch` call (successes only, and `apply_patch` is parsed for its `Add File` / `Update File` / `Delete File` / `Move to` path lines) — and a `requested` rule whose declared pattern matches one of those paths is rendered whole on the next request, for the rest of the session. All six scope keys the 22 conventions document are read: Claude Code, Cline and CodeBuddy's `paths`, Cursor / Trae / Continue / Windsurf / Devin / Antigravity's `globs`, Qoder's singular `glob`, JetBrains AI Assistant's `pattern`, Kiro's `fileMatchPattern` and Copilot's `applyTo`; the header of `src/attach.ts` carries the vendor URL each one was verified against. Matching is bounded like the rest of the plugin: at most 256 file-scoped rules compiled per request (`attach.limit`), at most 2000 touched paths remembered per session, a pattern skipped for backtracking risk or a compile failure (`attach.pattern`), and one that blows the 200 ms match budget dropped (`attach.slow`) — each with a diagnostic in the panel. The panel shows the state without relabelling the file: an attached rule keeps its *On demand* label, gains a green chip edge and the note *Body resident - this session touched a matching file*, and its cost moves out of the on-demand index and into the resident total, because that is where its body now is. The rule's own `type` is never rewritten: attachment is a per-request view, not an edit to the file or to its classification. Measured on a fixture workspace: a project rule scoped to `src/**/*.ts` reads as an index line until a `read` of `src/app.ts` succeeds, and is injected in full from the next step on. A touch list belongs to the working directory it was collected under: when the session moves to another tree the list is dropped, so no rule from a workspace the session has left stays resident.
- **A real-composition smoke test that needs no credentials.** `npm run test:e2e` boots a real DSH headless session - the repository is installed into a throwaway DSH home with `dsh plugin add` and DSH's own profile composer loads it - while a local OpenAI-compatible stub stands in for the model, so the run needs no API key. Assertions read the request bodies the stub recorded, never the plugin's own output: with the plugin enabled the first request carries `<rules>`, the resident rule's body and the on-demand rule's index line only, and the tool-continuation request reuses that block byte for byte; with the plugin line disabled no request carries `<rules>` at all, 2003 bytes smaller. Four adversarial runs cover an unreadable rules directory beside an unterminated frontmatter fence, a catastrophic glob, an empty project, and a 20000-character rule that truncates at `perRuleMax`. The layer skips itself with exit 0 when no launcher is resolvable. Multi-turn attachment stickiness is not asserted here: the headless template answers one task and exits, and the host hands the continuation step an empty claimed batch, so that behaviour stays covered by the fake-host suite. The layer's design and the official testing policy behind it are recorded in `docs/testing.md`.

### Fixed

- **Seven brand marks were invisible in the dark theme.** The vendored glyphs from simple-icons and the JetBrains plugins carry no `fill` of their own — SVG's default is black, and the source files relied on the page tinting them (or on a root `fill="none"` that the vendoring dropped). On the light surface that read as black-on-white, but on the dark panel surface it measured a WCAG contrast of **1.34** for Trae, Qoder, Cline, Windsurf, GitHub Copilot and Tabnine. The mark element now defaults to `currentColor`, so a monochrome glyph follows the theme while a mark that declares its own colours keeps them; Tabnine's stroke-only outline also got its `fill="none"` back, since without it the hexagon filled in as a solid block. Measured after the fix: **15.03 dark / 18.9 light** for the monochrome glyphs. The transparent-plate rule was also moved after the `.s-*` plates, which had been winning on source order and leaving four marks on a coloured chip.

- **The diagnostics filter could strand the panel on an empty list.** The view was held in two states at once — a boolean and the source dropdown — that any direct dropdown change (switching workspace, or picking "all sources") put out of step: the list was filtered by diagnostics twice, the count reached zero, and the stat button and the dropdown entry that could undo it both vanished with it, so there was no way back. The dropdown is now the single source of truth and both controls stay rendered while the view is on. Reproduced in a scratch host: diagnostics on in a workspace with one diagnostic, switch to a workspace with none, then pick "all sources" — the list stayed empty and no control remained.

- **Plain-markdown conventions scanned to nothing.** Roo Code, Junie, Amazon Q and Tabnine document no frontmatter vocabulary — every file in their directories applies to every request — but the classification gate required a rule-looking field or a `description`, so every file those four sources found was rejected as "not a recognizable rule file". The source table now answers that question per convention (`emptyRuleType`, see above), and a file that declares nothing at all from such a source derives to always-on instead of being dropped. Measured on a fixture workspace with twelve conventions present: twelve rules found and zero skips, where the same scan previously produced nine rules and three `classify.skipped` diagnostics for `roo.md`, `junie.md` and `tabnine.md`.

- **The panel could not scroll.** With 14 rules the content was 1621px tall inside a 1222px `.mainPanel`, but `.dshrm-panel` declared no height and `overflow: visible`, so the clipping happened one level up in `.centerCol` (`overflow: hidden`) and nothing on the page scrolled — the last 399px were unreachable. The panel is now its own scroller (`height: 100%` plus `overflow-y: auto`), the same shape the host's plugin-manager page uses. Verified in a scratch host: `clientHeight 1222 / scrollHeight 1621`, the last rule visible at the bottom.

- **A file whose every line is a call expression is not a rule.** CodeBuddy admits a file with no rule fields, which let a Codex command-permission list (`prefix_rule(pattern=["ls"], decision="allow")`, named `*.mdc`) into the prompt when one sat in a CodeBuddy rules directory. Content that is nothing but calls is now rejected for every convention, alongside three other shapes no agent documents as a rule: binary content, a `---` fence that is opened and never closed, and a file with no text at all.

- **Eight fields the parser read past, and one value it rejected.** Cline writes its `paths` as a block list and annotates every entry (`- "src/**"  # All files under src/`); the comment was cut from closed-vocabulary scalars only, so the quotes were peeled off a value that still carried `# All files under src/` and the glob was dead. The singular spellings of the same idea were dropped outright — Qoder's `glob` ("equivalent to `trigger: glob` + `glob`"), Antigravity's singular `glob`, Kiro's `fileMatchPattern` (the only source of a `fileMatch` rule's globs) and JetBrains' `pattern` — as were Trae's `scene` (a file whose only field it is is a documented git-commit rule), Continue's `regex` (which scopes a rule by file *content*, so a regex-only rule now derives to requested instead of being read as a file that declares nothing) and Copilot's `excludeAgent`. Copilot's `excludeAgent` and CodeBuddy's `updatedAt` / `provider` are kept in `values` for the same reason: a field discarded on read can never be round-tripped by a future editor. Finally, `type: always on` — the value in the rule file JetBrains' own AI Assistant documentation links to — no longer trips the unknown-type gate that was rejecting the vendor's published example. New tests cover each shape.

- **Qoder's documented user-level rules directory is now read.** `~/.qoder/rules` appears on the CLI page's storage-locations table ("User-Level | ~/.qoder/rules/**/*.md"), where the IDE page prints the project tier alone; the row had shown no user tier since the source was added, so personal Qoder rules were never scanned.

- **Three brand marks were painted as solid blocks.** The badge gives every glyph `fill: currentColor`, and a shape that carries a stroke and no fill of its own inherits it: Qoder's ring, Qoder CN's copy of it, and Cursor's outer ring each filled their own outline and covered the shapes beneath. Qoder read as a black block with the mark half hidden behind it, and Cursor lost its cube to the plate. Each of the three shapes now declares `fill="none"`, and a test walks every vendored mark to reject a stroke without a fill.

- **Trae CN had no mark.** Its chip drew two letters while the TRAE chip beside it drew the glyph, even though the CN site serves the same favicon — byte for byte, 48x48, sha256 49d523938a22af5a70dd79923725df38674823026e2f917e76337319969f4af4 — and neither site publishes an SVG.

- **Qoder's mark was the wrong artwork.** The entry had been cut out of an inline SVG on the qoder.com home page, which is a laptop-and-person illustration rather than the mark, and the note beside it claimed the vendor served no standalone SVG. It does: `https://qoder.com/favIcon.svg` is the mark on its plate, and the entry is now that file, minified at floatPrecision 0.

- **A scan problem said what went wrong but never where.** The stat bar rendered every finding as a sentence of explanations joined by semicolons — "the field was declared but has no entries" with no field name, no line and no file. The same finding was already carried with its code, detail, line and file in both directions; the rendering threw the last three away. The count is now expandable into one row per finding, and a path that the detail already ended with is not printed twice.
- **The cost dialog's last row was unreadable to anyone who had not written it.** *Request index* / "Fixed tags and preamble around the on-demand lines" described the implementation, not the number: the tags and instructions wrapped around the on-demand index lines, resident whenever any rule is on demand and belonging to no single rule. It is now *On-demand index overhead* with that sentence, and the footnote says the row above the total is the wrapper those lines sit in. The Details link beside the total also switched from the brand token to the business-state token, matching the colour of the On demand label it opens onto.

- **A numeric setting could be pinned to a value it could not mean.** Every cap in the config schema was a bare `z.number().default(...)`, so the schema checked the type and nothing else. Measured before the change: `perRuleMax: -1` was accepted and truncated every always-on rule at `-1 chars` - a truncation note longer than the cap it announces - `NaN` skipped truncation entirely because every comparison against it is false, and `maxScanDepth: -3` returned no rules and no diagnostics at all. Each number now carries `.step(1).min().max()`, so a fraction, a `NaN` or an out-of-range pin is refused while the settings load, and the schema message names the bound that was crossed.
- **A failed write reached the panel as a transport error instead of a reason.** `handleAction` chained each write onto `writeChain` and returned the queued promise; the chain deliberately swallowed the rejection so one failed write could not wedge every later one, which also meant nothing ever turned that rejection into a response. A `writeState` failure - a directory squatting on the temp path, a state directory that cannot be created - surfaced in the browser as a bare failed fetch. The handler now catches the queued rejection and answers `500` with the error text, which is what the panel renders.
- **`read_rules` dropped an ambiguous key without saying so.** A key that matched more than one rule (a bare basename present in two directories, for instance) was collected into `resolution.ambiguous` and then never rendered, so the model received a result that looked clean while one of its requested rules was silently absent. The result now lists every candidate absolute path with a retry hint, the tool value carries `ambiguousCount`, and the tool description tells the model to retry with one exact path.
- **`state.json` was read at any size and written through any link.** The settings file was parsed whatever its length, and `writeState` renamed its temp file over whatever sat at the target - including a symbolic link, which it replaced with a regular file and silently discarded the indirection. Reads now stop at a 1 MiB ceiling and fall back to the defaults, and a write refuses a symbolic-link target before the temp file exists, so a refusal leaves the directory, and any existing `state.json`, byte for byte as it was.

### Removed

- **A vendored brand mark no source could ever render.** WorkBuddy's logo sat in `src/client/brand-icons.ts` from before the source table was final, but WorkBuddy's rules are the CodeBuddy convention — `src/scan.ts` documents why it needs no entry of its own — so no family the classifier can produce would ever look it up. The bytes shipped to every client and drew nothing. It is gone, and a delivery check now fails the build when an icon key is not in the `RuleFamily` union.

- **Augment Code's user rules obeyed frontmatter the vendor ignores.** The guidelines page states that rules under `~/.augment/rules/` are "always treated as `always_apply`" and "do not support other frontmatter types", while workspace rules "support all three types (Always, Manual, Auto)". The scan table now carries a per-tier answer, so a user-level rule reads as always-on no matter what it declares, the project tier keeps the ordinary derivation, and a `type.tierOverridden` diagnostic marks the file whose declared state was overruled.

- **The entry cap never fired for a flat directory.** `MAX_SCAN_ENTRIES` was tested once per directory, before `readdir`, so a source root whose files all sat in one directory — the shape that reaches the cap first — was enumerated in full while the scan still reported itself complete and untruncated. The check now runs per entry, so both the cap and the truncation notice apply to that shape.

- **Three unreferenced panel strings** (`summary`, `sourceOn`, `sourceOff`) dropped from both dictionaries. The switch they described is a plain iOS-style checkbox and never had a text label.

## [0.1.0] - 2026-11-18

First release.

### Added

- **Three-state rules.** Each rule is classified as always-on, on demand, or disabled, derived from frontmatter with the same precedence CodeBuddy uses: a declared `type`, then `alwaysApply`, then a non-empty `description`, then manual.
- **Cross-agent scanning.** Read-only sources for CodeBuddy (public and intranet forms), Cursor, and Claude Code, at both user and project scope. Project root is the nearest ancestor containing `.git`.
- **On-demand loading.** A `<rules>` block carrying each on-demand rule's absolute path and description is injected from an `agent/pre-step` listener. Bodies load through the `read_rules` tool only when a description matches the task. Measured on a real project: 943 resident tokens against 9,934 if every rule were resident.
- **`read_rules` tool.** Four-tier key resolution (exact path, case-insensitive path, unique basename, unique rule name) that reports ambiguity with candidates rather than guessing. Output is capped at 60000 characters and consumed in order, so earlier rules are served in full.
- **Budgets.** Per-rule cap with truncation, plus per-tier totals with whole-item omission; a line naming what was dropped is rendered into the block.
- **ReDoS screen for `globs` / `paths`.** Patterns with eight or more single stars and a short literal between them are rejected before compilation. Thresholds measured against picomatch 4.0.7.
- **Token cost display.** CJK-aware estimation with per-rule badges and a resident-total summary.
- **Settings and sidebar panels.** Registered through `settings.section` with a matching icon id, plus `sidebar.panellist`. Entry placement is switchable, and at least one entry is always retained so the panel cannot become unreachable.
- **Panel styling.** One injected `<style>` element, theme-following through DSH's `--dsw-*` alias tokens, each with a literal fallback so a renamed token still renders. Injection is idempotent by element id, and skipped when no document exists.
- **Read-only guarantee.** Sources declare `mutable: false`; a test asserts it, and no code path writes to a scanned directory.

### Fixed during development

Recorded because each was found by running the code rather than reading it:

- **Surrogate-safe truncation.** CodeBuddy's own `safeSlice` tests the low-surrogate range, which drops a complete pair and returns a lone high surrogate. Measured on `"ab😀cd"` with a limit of 4, that version returns `"ab\uD83D"` instead of `"ab😀"`. This implementation tests the high range, and a test walks every cut position.
- **Classification order.** Deciding a rule's family from frontmatter order alone misclassifies Cursor's documented example, which carries `description`, `globs`, and `alwaysApply` together. Family now comes from the source directory; frontmatter decides only whether a file is a rule at all, and refines within `.codebuddy`.
- **Diagnostics for rejected files.** Rejected files were skipped before their skip reason was collected, so the reason never reached the panel. Diagnostics are now collected ahead of the skip.
- **Silently dropped tiers.** A tier rendered only when it had kept content, so when budget dropped *every* rule in a tier, the omission notice disappeared with them and the rules vanished without a trace. A tier now renders when it has kept content **or** anything was omitted.
- **Unwired configuration.** All seven declared config fields (`perRuleMax`, `userRulesTotal`, `projectRulesTotal`, `readRulesOutput`, `maxScanDepth`, `injectRules`, `stateDir`) were read by nothing: `apply` did not even accept a `config` parameter, and each site used a hard-coded constant. `apply(ctx, config)` now threads every field through, and `tests/config.spec.ts` proves each one takes effect.
- **Injection position, against the host's own convention.** The rules block was appended to the end of the step's batch. The host's `dsh-agent-instructions` folds its context *immediately after the claimed batch*, so the direct prompt precedes it and driver-appended runtime context follows it — the opposite order. Placing it at the end also meant a first step with an empty batch would inject and manufacture a request the turn does not own. Placement is now a pure function (`src/inject.ts`) with 18 tests, matching the host on all three points: insertion index, the empty-first-batch guard, and identity-based matching of the claimed batch.
- **`picomatch` options.** `posixSlashes` is a micromatch option and is absent from picomatch's types. Separators are normalized before matching instead.
- **`as never` on the message source.** The injected message's `source` was cast to silence the compiler, which also made it invisible to every consumer. It is now declared through `MessageSourceMap` module augmentation — the same seam the host's own `dsh-agent-instructions` plugin uses.

### Changed before first release

- **Renamed to `@one-dragon/dsh-rules-manager`.** The bare name `dsh-rules-manager` is taken on npm by an unrelated DSH plugin (20 versions, still active). The scoped name is unambiguous and cannot be squatted. The cordis entry id stays the short `rules-manager`, matching the convention the reference plugin uses.
- **`.gitignore` no longer excludes `lib/`.** `main` points at `lib/index.js` and the client half is `lib/client.js`, so a checkout without them cannot be added as a bundle. The same decision, with the same comment, appears in the sibling DSH plugins. A delivery check now guards it.
- **`repository`, `bugs`, and `homepage` added.**

### Verified

- **225 tests across 14 files** passed at release time. The suite has grown since; run `npm run test` for the current count.
- **Real-machine load**: installed into a scratch DSH profile, then composed by DSH's own loader — `--dump-config` produced a tree containing this plugin with no errors, and `--dump-config-schema` resolved the `Config` schema with all documented defaults.
- **Real-project integration**: the 14 rule files of a live project scan, classify, render, and serve through `read_rules` correctly, with 943 resident tokens against 9,934 if every rule were resident. See `tests/integration/real-project.mts` for the same run in script form.

### Notes

- `globs` / `paths` were parsed and retained without being used for automatic attachment; attachment happened through the description tier only. File-scoped attachment landed in [Unreleased].
- `bash` file access is not tracked, matching the host instruction plugin's deliberate choice.
- Requires DSH `>=0.2.2-rc.1 <0.3.0-0` and Node `^22.19.0 || >=24.0.0`.
